# Feature specs

One short spec per feature. Specs are living documents: update them when
behavior changes. Each spec has the same sections: user story, behavior, UX,
acceptance criteria, provenance.

The `Provenance:` line lists the sources the spec was written from (see the
clean-room rules in `CLAUDE.md`). Allowed sources: the maintainer's
descriptions, public papers, open standards, general garment-making knowledge.
